# gateway（统一网关层）

结论（技术架构 §三）：**要有，且只有一个**。职责边界 = "请求级横切语义"；一切带业务语义的东西下推给 BFF 与服务。

## 选型（待拍板④，当前工作默认）

**云托管网关（阿里云 MSE 云原生网关 / Higress）**——Ingress 与 API 网关合一（少一跳）、无 etcd 运维、与云 WAF/证书/SLS 原生联动；支付回调这类"网关挂=钱断"路径的可用性外包给云厂商。
备选 APISIX 仅在需要写自定义插件（反爬做深）或明确保留换云自由时成立。一↔二的唯一决策变量是**对云厂商锁定的立场**。

## 职责分界

- **进网关**：TLS 终结、路由、WAF/DDoS、粗粒度与按身份限流、灰度分流、访问日志、IP 白名单、CORS。
- **禁止进网关**：聚合裁剪（BFF 的存在理由）、业务鉴权决策（RBAC 在 admin-bff、登录态交换在 identity）、渠道签名验证（碰密钥、语义属接收方，网关只做 IP 白名单外壳）。
- admin 的"统一"方式：**同一网关集群，不同域名 + 不同策略组**（IP 白名单/办公网准入），策略分离靠配置不靠双套部署。
- 图/视频流量走 CDN→OSS 直出，不过网关；网关只扛 JSON API。
- 本系统两个边缘层刚需：**内容资产反爬**（户型方案库是护城河）、**小程序审核期服务端灰度**（按版本路由）。

## 入口清单

| 入口 | 路由目标 | 特征 |
|---|---|---|
| C 端 API | c-bff | 脉冲流量（业主群转发瞬时爆发）、需反爬 |
| 管理端 API | admin-bff | 低流量、高权限、IP 白名单/办公网准入 |
| 微信支付回调 | trade-svc | 资金关键路径，IP 白名单 + 最高可用性 |
| IM 事件 | channel-svc | 首发飞书；**选长连接模式时此入口为 channel-svc 主动外连，不经网关**；微信系接入后微信服务器直连走此口（`/api/v1/channels/{channel_type}/webhook`） |
| 联盟转化回调 | shelf-svc | 归因数据源，丢失=丢钱 |
| AIDCP 回调 | genpipe-svc | 既存系统跨界调用，按"外部系统+API 契约"对接 |
